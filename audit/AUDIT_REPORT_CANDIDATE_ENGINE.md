## ⛔ ประเด็นตัดสิน: เปลี่ยน Business Rule โดยไม่มีการอนุมัติ [C1]

| | V1/V2/V3 (กติกาที่ใช้เบิกเงินอยู่) | Candidate Engine |
|---|---|---|
| ปลายทางสุดท้าย | **จุดไกลสุดจากคลัง** (กติกาตายตัว) | จุดใดก็ได้ใน Top-3 ที่ให้ **ระยะรวมสั้นสุด** |
| ผลต่อยอดเบิก | คงที่ ตรวจสอบย้อนหลังได้ | **ระยะเบิกลดลง/เปลี่ยนได้** ตามผล API แต่ละครั้ง |

นี่ไม่ใช่ "การแก้บั๊ก" แต่คือ **การเปลี่ยนสูตรคำนวณเงินเบิก** ระยะทางที่ได้จะ ≤ เดิมเสมอ
(ผู้ขับได้เงินน้อยลง) — การเปลี่ยนแบบนี้ต้องได้รับอนุมัติจากเจ้าของธุรกิจก่อน ไม่ใช่ตัดสินใจโดย AI

## 🔴 บั๊กร้ายแรงที่พิสูจน์ด้วยการรันโค้ดจริง

### [C2] `(distanceMeters || 0)` ทำให้ candidate ที่ข้อมูลหาย "ชนะ" ด้วย 0 กม.
```
ทดสอบ: A=152km, B=undefined, C=148km → ผู้ชนะ = B ระยะ 0 km  ← ผิดร้ายแรง!
```
เพราะโค้ดเลือก **minimum** — ค่า 0 จาก `|| 0` จึงชนะทุกกรณี → ชีตถูกเขียน `ระยะทาง = 0`
พร้อม Status Success = ยอดเบิก 0 บาทแบบเงียบสนิท (silent error ที่อันตรายที่สุดในทั้ง 3 เวอร์ชัน)

### [C4] ไม่มี retry + candidate fail ข้ามเงียบ → ผลไม่คงที่ (non-deterministic)
```
ทดสอบ: รอบ 1 ผู้ชนะ = B (148km) | รอบ 2 B โดน 429 ชั่วคราว → ผู้ชนะ = C (150km)
```
ระบบเบิกเงินต้องได้ผลเดิมทุกครั้ง (จึงใช้ TRAFFIC_UNAWARE อยู่แล้ว) — แต่สถาปัตยกรรมนี้ทำให้
**เลข กม. เปลี่ยนตามดวงของ network** ขัดหลักการตรวจสอบย้อนหลังโดยตรง

### [C7] เขียน 20 คอลัมน์แบบ positional ล้วน — **แย่กว่า V2**
```
ทดสอบ: มีคอลัมน์ "หมายเหตุ" แทรกหลัง _02 → จุดที่ 3 ถูกเขียนทับลงคอลัมน์ "หมายเหตุ"
```
V2 ยังตรวจ presence, V3 ตรวจ contiguity — เวอร์ชันนี้**ไม่ตรวจอะไรเลย** (`firstDestColIndex + i`)

### [C3] ต้นทุน API x3 ทุกการรัน
ยิง `computeRoutes` + `optimizeWaypointOrder` (Advanced SKU) 3 ครั้งต่อ 1 shipment เสมอ
→ **ค่าใช้จ่าย Google Maps เพิ่ม 3 เท่า** ถาวร โดยผลลัพธ์ 2 ใน 3 ถูกทิ้ง และไม่มี cache ใดๆ

## 🟠 บั๊กเพิ่มเติม

- **[C8]** เขียนทั้งแถวแบบ read-modify-write (`getValues` ทั้งแถว → แก้ → `setValues` ทั้งแถว)
  → ค่าที่ AppSheet sync เข้ามาแก้ในคอลัมน์อื่น**ระหว่าง**ช่วง read→write จะถูกทับด้วยค่าเก่า
  (LockService ล็อกได้เฉพาะ script executions ไม่ได้ล็อก AppSheet/ผู้ใช้แก้ชีต)
- **[C9]** `optimizedIntermediateWaypointIndex` ตรวจแค่ `if (intermediates[idx])`
  → index ไม่ครบ = จุดหายจากสตริง/ลิงก์ ขณะ `totalDistance` รวมครบทุกจุด (ทดสอบ: 3 จุดเหลือ 2)
  → ข้อมูลในชีตขัดแย้งกันเอง (ระยะ 3 จุด แต่พิกัดแสดง 2 จุด)
- **[C10]** ไม่ตรวจลิมิต 25 intermediates / JSON.parse ไม่มี try-catch /
  lock ครอบทั้ง flow รวม API call (ค้าง 30–60 วิ/งาน — งานอื่นต่อคิวจน timeout) /
  พิกัด `parts.length !== 2` ถูกข้ามโดยไม่บันทึกแม้แต่ log

## ✅ สิ่งที่เวอร์ชันนี้ทำได้ดี (แนวคิดที่เก็บไว้พิจารณา)

1. `UrlFetchApp.fetchAll()` — เทคนิค parallel fetch ถูกต้องตามหลัก Apps Script
